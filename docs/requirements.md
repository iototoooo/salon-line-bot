# 要件定義書：美容室向け LINE bot＋AI自動応答システム

- 案件区分：AI開発講座 初級編・案件1（模擬受託案件）
- 版数：v0.1（設計フェーズ / Step 2）
- 作成日：2026-11-10
- 前提：ヒアリング回答は教材で確定済み。追加ヒアリングは行わない。

---

## 1. 背景と目的

個人経営の美容室では、LINE公式アカウント（友だち約300人）に1日10〜15件の問い合わせが届き、オーナーが施術の合間に手作業で返信している。問い合わせの多くは定型的な質問（営業時間・カット料金・予約の可否・パーマとカラーの同時施術・駐車場）である。

本システムの目的は次の3点である。

1. 定型的な質問に AI が24時間すぐに回答し、オーナーの返信負担を減らす
2. AI が回答できない質問を確実にオーナーへ引き継ぎ、取りこぼしを防ぐ
3. 臨時休業などのお知らせを、誤送信を防ぎながら一斉配信できるようにする

## 2. スコープ

### 2.1 やること（Phase 1）

| No | 項目 | 概要 |
|----|------|------|
| S-1 | LINE 自動応答 | LINE Messaging API の Webhook でメッセージを受け、Claude API で回答を生成して返信する |
| S-2 | FAQ・メニューに基づく回答 | 回答の根拠は DB に登録された FAQ とメニュー（料金）のみに限定する |
| S-3 | 回答不能時のオーナー通知 | AI が回答できない／回答すべきでない質問は、お客様に定型文を返し、オーナーへ通知する |
| S-4 | 会話ログの保存 | 受信メッセージ・AI回答・判定結果を保存し、管理画面で確認できる |
| S-5 | 管理画面（オーナー用） | ログイン、FAQ 編集、メニュー・料金編集、会話ログ閲覧、未対応一覧、自動応答 ON/OFF |
| S-6 | お知らせ一斉配信 | 管理画面から臨時休業などを配信。プレビュー・テスト送信・配信数／費用確認・最終確認を必須とする |
| S-7 | 運用ドキュメント | オーナー向け操作マニュアル、料金改定時の更新手順 |

### 2.2 やらないこと（Phase 1 の対象外）

- 予約の受付・変更・キャンセル、および空き状況の回答（AI に予約状況を推測させない）
- 外部予約システム（ホットペッパービューティー等）との連携
- 顧客管理（カルテ、来店履歴、会員ランク）
- 決済、クーポン発行、ポイントカード
- セグメント配信（属性別・タグ別配信）、配信予約（日時指定）
- 画像・スタンプ・音声メッセージの内容解析（受信時は定型文で案内し、オーナーへ通知）
- 多言語対応
- AI がオーナーの代わりに個別の相談（髪質・薬剤アレルギー等）に判断を下すこと
- 既存 LINE 公式アカウントのリッチメニュー等の大幅な作り替え

## 4. 機能要件

### 4.1 自動応答（LINE）

| ID | 要件 |
|----|------|
| F-01 | テキストメッセージを受信したら AI が回答を生成し、LINE の応答メッセージ（reply）で返信する |
| F-02 | 回答は FAQ・メニュー・店舗基本情報（営業時間・定休日・住所・駐車場・電話番号・予約方法）の登録内容のみを根拠とする |
| F-03 | 登録情報で回答できない質問には推測で答えず、「確認してご連絡します」旨の定型文を返し、オーナーへ通知する |
| F-04 | 予約の空き状況・予約の確定について問われた場合、AI は空き状況を答えず、登録された予約方法（電話番号・予約ページ等）を案内する。必要に応じてオーナーへ通知する |
| F-05 | テキスト以外（画像・スタンプ・位置情報等）を受信した場合は定型文を返し、内容に応じてオーナーへ通知する |
| F-06 | 管理画面で自動応答を OFF にした場合、AI は使わず「担当者から折り返します」等の定型文のみを返す（緊急停止スイッチ） |
| F-07 | 同一イベントの再送（Webhook の再配信）では二重に返信しない |
| F-08 | 友だち追加（follow）時のあいさつは LINE 公式アカウント側の設定を利用し、本システムでは扱わない（重複送信防止） |

### 4.2 オーナー通知

| ID | 要件 |
|----|------|
| F-11 | AI が回答不能と判定した質問、テキスト以外の受信、AI 処理エラー時に、オーナーへ通知する |
| F-12 | 通知には「受信日時・質問内容の要約・管理画面の該当ログへのリンク」を含める。お客様の個人情報は必要最小限とする |
| F-13 | 未対応の問い合わせは管理画面の「未対応一覧」に表示し、オーナーが「対応済み」にできる |

### 4.3 管理画面

| ID | 要件 |
|----|------|
| F-21 | オーナーのみがログインできる（メール＋パスワード、またはマジックリンク） |
| F-22 | FAQ の追加・編集・削除・公開／非公開切替 |
| F-23 | メニュー（カット・カラー・パーマ等）と料金の追加・編集・削除。料金改定（年2回程度）をオーナー自身で行える |
| F-24 | 店舗基本情報（営業時間・定休日・駐車場・予約方法など）の編集 |
| F-25 | 会話ログの一覧・検索（日付、未対応のみ） |
| F-26 | 自動応答 ON/OFF の切替 |
| F-27 | 回答テスト機能：LINE に送らず、管理画面上で質問を入力して AI の回答を確認できる |

### 4.4 お知らせ一斉配信

| ID | 要件 |
|----|------|
| F-31 | 本文を作成し、下書き保存できる |
| F-32 | LINE での見え方をプレビューできる |
| F-33 | 本番配信前に、オーナー自身の LINE へテスト送信できる |
| F-34 | 配信前に「配信対象人数（友だち数の目安）・今月の送信可能数の残り・配信後の残り見込み」を表示する |
| F-35 | 送信可能数を超える、または超えそうな場合は警告し、配信ボタンを無効化する（追加費用の発生を防ぐ） |
| F-36 | 最終確認として、確認文言の入力（例：「配信する」と入力）を求める二段階確認を行う |
| F-37 | 二重クリック・再送による二重配信を防止する |
| F-38 | 配信履歴（日時・本文・配信数・結果）を保存する |

## 5. 非機能要件

| 区分 | 要件 |
|------|------|
| 応答性 | お客様への返信は、通常時おおむね10秒以内を目標とする（AI API の応答時間に依存） |
| 可用性 | 個人店のため SLA は設けない。AI API 障害時も定型文を返して通知する（無応答にしない） |
| 正確性 | 登録情報にない内容を回答しない。予約状況は回答しない。料金は DB の値をそのまま提示する |
| セキュリティ | LINE 署名検証を必須とする。API キー類は環境変数で管理しコードに含めない。管理画面は認証必須。DB は行レベルセキュリティ（RLS）を有効化する |
| 個人情報 | 保存するのは LINE ユーザーID・表示名（任意）・メッセージ本文のみ。会話ログの保存期間は既定90日（クライアントと合意の上で変更可）。プライバシーポリシーへの記載をクライアントに依頼する |
| 運用性 | オーナーがコードを触らずに FAQ・料金・営業情報を更新できる |
| コスト | 月額費用を最小化する。各サービスの料金・無料枠は契約前に公式情報で再確認する（本書作成時点で未確認） |
| 規約順守 | 各サービスの利用規約（特にホスティングの商用利用条件、LINE の利用規約、AI API の利用ポリシー）に適合する構成とする |
| 保守性 | Next.js（App Router）＋TypeScript で型安全に実装し、主要ロジックにテストを用意する |
| ログ | エラーはサーバーログに記録。会話ログとは別に、個人情報を含まない形で記録する |

## 6. 受け入れ基準

以下をすべて満たした時点で納品とする。テストは本番前の検証用環境（テスト用 LINE 公式アカウント）で行い、最後に本番アカウントで最小限の確認を行う。

### 6.1 自動応答

| No | 確認内容 | 合格条件 |
|----|----------|----------|
| AC-01 | 「営業時間は？」 | 登録された営業時間・定休日を正しく回答する |
| AC-02 | 「カットはいくら？」 | メニューに登録された料金と一致する金額を回答する |
| AC-03 | 「明日の14時って空いてますか？」 | 空き状況を答えず、予約方法（電話番号等）を案内する |
| AC-04 | 「パーマとカラーって同時にできますか？」 | FAQ の内容に沿って回答する |
| AC-05 | 「駐車場はありますか？」 | 登録内容に沿って回答する |
| AC-06 | FAQ にない質問（例：「〇〇ブランドのシャンプーは売ってますか？」） | 推測で答えず定型文を返し、オーナーに通知が届き、未対応一覧に表示される |
| AC-07 | スタンプ・画像の送信 | 定型文を返す。エラーにならない |
| AC-08 | 管理画面で料金を変更 → 同じ質問 | 変更後の料金で回答する（再デプロイ不要） |
| AC-09 | 自動応答 OFF | AI を使わず定型文のみ返る |
| AC-10 | AI API が失敗する状況（キー無効化など） | 定型文を返し、オーナーに通知される |
| AC-11 | 同一イベントの再送 | 返信が1回だけである |
| AC-12 | 想定質問20問のテストセット | 18問以上で適切（誤った料金・誤った予約可否の回答は0件であること） |

### 6.2 管理画面・一斉配信

| No | 確認内容 | 合格条件 |
|----|----------|----------|
| AC-21 | 未ログインで管理画面にアクセス | ログイン画面へ誘導され、データは表示されない |
| AC-22 | FAQ・メニュー・店舗情報の編集 | オーナーが単独で操作できる（マニュアルを見ながら） |
| AC-23 | テスト送信 | オーナーの LINE にのみ届く |
| AC-24 | 一斉配信の確認画面 | 配信対象数と残り送信可能数が表示され、確認文言の入力なしでは送信できない |
| AC-25 | 送信可能数不足の状態 | 配信ボタンが無効になり警告が出る |
| AC-26 | 配信ボタンの連打 | 配信は1回のみ |

### 6.3 納品物

- ソースコード（Git リポジトリ）
- 本番環境（クライアント名義のアカウントで構築）
- 本書・システム設計書・オーナー向け操作マニュアル
- 環境変数・アカウント情報の引き継ぎ一覧（秘密情報は安全な方法で別途受け渡し）
